Этот скилл описывает обязательные соглашения по написанию C# кода в проекте.
Следуй им при создании любого нового кода и при редактировании существующего.

## XML Summary документация

Каждый **класс**, **public метод** и **public свойство** обязаны иметь XML summary комментарий.

```csharp
/// <summary>
/// Краткое описание того, что делает класс или член.
/// </summary>
```

Правила:
- Summary пишется на русском языке
- Описание должно быть кратким и по существу — одно предложение
- Для методов описывай действие, а не реализацию: "Загружает данные из базы", а не "Вызывает метод репозитория"
- Приватные члены класса summary не требуют

## Именование приватных полей

Приватные поля пишутся с маленькой буквы, без префикса подчёркивания `_`.

```csharp
// ✅ Правильно
private readonly string connectionString;
private int retryCount;

// ❌ Неправильно
private readonly string _connectionString;
private int RetryCount;
```

## Объявление переменных через var

Все локальные переменные внутри методов объявляются через `var`, а не через явный тип.

```csharp
// ✅ Правильно
var result = await repository.GetAllAsync();
var count = items.Count();
var config = new ConfigurationBuilder().Build();

// ❌ Неправильно
List<Hero> result = await repository.GetAllAsync();
int count = items.Count();
IConfigurationRoot config = new ConfigurationBuilder().Build();
```

Исключение: допустимо указывать тип явно, если `var` делает код неоднозначным и тип нельзя понять из контекста — но такие случаи редки.

## Сводная шпаргалка

| Правило | Правильно | Неправильно |
|---|---|---|
| Summary на классе | `/// <summary>...</summary>` | Отсутствует |
| Summary на public методе | `/// <summary>...</summary>` | Отсутствует |
| Summary на public свойстве | `/// <summary>...</summary>` | Отсутствует |
| Приватное поле | `someField` | `_someField`, `SomeField` |
| Локальная переменная | `var x = ...` | `Type x = ...` |
